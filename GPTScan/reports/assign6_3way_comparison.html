Kennzahlen erklärt. Recall = TP / N — Anteil der echten Lücken, die gefunden wurden (Vollständigkeit). Precision = TP / (TP + FP) — Anteil der Findings, der wirklich die gelabelte Lücke trifft (Signalqualität). F1 = 2·P·R / (P + R) — harmonisches Mittel beider.

Interpretation. Mythril meldet wenig und präzise, verpasst aber die meisten Lücken (hohe Precision, niedriger Recall). LLMSmartAudit findet fast alle Lücken, ertränkt sie aber in Zusatz-Findings (hoher Recall, niedrige Precision). GPTScan ist auf DeFi-Logik-Schwachstellen (MWE-200..209) spezialisiert; auf diesem klassischen Set liegt keine der gelabelten Schwachstellen in seinem Detektor-Umfang. Es meldet daher 0 Findings — verpasst die klassischen Lücken (Recall 0), erzeugt aber auch null Rauschen (0 False Positives). Es misst hier den Scope, nicht die Fähigkeit.

Hinweis. FP zählt jedes Finding jenseits der gelabelten Lücke. † Precision und F1 sind für GPTScan undefiniert (0/0), da es keine Findings meldet — nicht 0 %.

‡ Zur GPTScan-Ausführung. GPTScans Funktions-Parser (gebündelte ANTLR-Solidity-Grammatik) akzeptiert die Alt-Syntax (constant/var) der 0.4.x-Originale nicht; GPTScan lief daher auf den inhaltsgleichen SmartBugs-0.6.12-Ports derselben 10 Contracts (identische Contracts + gelabelte Schwachstellen; Mythril/LLMSmartAudit bleiben die 0.4.x-Referenzwerte). Live-Lauf: 17 LLM-Aufrufe ($0.0027). 7/10 Contracts wurden real analysiert (Funktionen extrahiert), davon Government, OpenAddressLottery, SmartBillions sogar vom LLM geprüft und in der Static-Confirmation-Stufe verworfen → 0 Findings, 0 False Positives. ERC20, ReturnValue, SimpleDAO konnten nicht analysiert werden (Parser extrahierte keine Funktionen) — auch sie lägen jedoch außerhalb von GPTScans DeFi-Logik-Scope.
